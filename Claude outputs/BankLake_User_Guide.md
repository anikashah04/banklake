# How to use BankLake

BankLake is a demonstration of a modern banking data platform built on fictional data. This guide is for anyone opening the website, including people with no technical background.

## The idea in one paragraph

Think of a water treatment plant. Raw water comes in from many sources (the bank's systems). It is collected untouched (Bronze), the daily changes are applied (Silver Merge), it is filtered, checked and made safe to share (Silver Transform), and finally bottled in ready-to-use form (Gold). BankLake also keeps a record of every drop that went through, and checks that the amount that went in equals the amount that came out.

## Quick start

1. **Open the site.** Run `streamlit run dashboard/app.py` in the project folder. The site opens in your browser at http://localhost:8501.
2. **Create the sample data.** On **Start here**, press **1. Create data**. This makes fictional customers, accounts and transactions, including a few deliberate mistakes so the checks have something to find. It wipes anything created before.
3. **Process it.** Press **2. Process data**. The first run takes a minute or two (the data engine needs about ten seconds to start). It cleans the data, hides personal details and builds the reports.
4. **Check it.** Press **3. Check results**. You get a green tick if every record can be accounted for.
5. **Explore.** Open **Business insights** for charts, **Look up a customer** for one person's picture, **Privacy & access** to see masking and roles, and **Activity & alerts** for the diary of what happened.
6. **Try the day-two story.** Back on **Start here** press **Add a day of new activity**, then process and check again. New, changed and deleted records are applied without reloading everything.

## Simple view and Technical view

The left bar has a **View** switch. *Simple* shows seven pages written in everyday words. *Technical* adds the engineering pages (Ingestion, Bronze, Silver Merge, Silver Transform, Gold, Control room, SQL migration, Table journey, Data explorer). Every page has a **What am I looking at?** box at the top.

## Roles

The role picker in the left bar is a demonstration. It is not a login: anyone can choose any role. It exists to show how access control and its audit trail work. A real deployment would take the role from the bank's sign-in system.

| Role | What it can see |
|---|---|
| executive, analyst | See masked values only (stars). |
| branch_manager | Can unmask customer names, not phone numbers or emails. |
| relationship_manager | Can unmask names, emails and phone numbers of customers. |
| compliance_officer, admin | Can unmask everything; admin can also change masking rules and permissions. |

## A five-minute demo

- **0:00 Explain** — Read the water-plant analogy on Start here. Say the data is fictional and generated, with deliberate errors.
- **0:30 Create and process** — Press steps 1 and 2 (or run them beforehand and start from the result).
- **1:30 Business value** — Business insights: show one branch chart and one customer chart. These come only from the finished reports.
- **2:30 Trust** — Can I trust the data?: press Run the checks and show the green result. Open the technical details and point at the records that were set aside with a reason.
- **3:30 Break it on purpose** — In the same page open Break something on purpose, delete 25 accounts, run the checks again. The red result names the first step where records went missing. Press Repair and check again for green.
- **4:30 Privacy** — Privacy & access: as analyst you see stars, as relationship manager you can unmask; show the refusal and the log entry.
- **5:00 Close** — Activity & alerts: show that every step above was recorded.

## Glossary

| Term | Meaning |
|---|---|
| Synthetic data | Fictional data generated by the project. No real person, bank or client is involved. |
| Lakehouse | One storage area (files) that is organised in layers so it can serve both reports and detailed analysis. |
| Raw data | The source files exactly as they arrive. |
| Bronze | The first layer: an untouched copy of the raw data, plus the file name and load time. |
| Silver Merge | The second layer: applies inserts, updates and deletes so each table shows the current truth. |
| Silver Transform | The third layer: cleaning, rule checks and masking. Bad records are set aside. |
| Silver | The result of Silver Transform: clean, checked, masked tables. |
| Gold | Business-ready summary tables built from Silver. |
| Quarantine | A separate area where rejected records are kept together with the reason, so nothing disappears silently. |
| CDC (change data capture) | Sending only what changed (new, updated, deleted records) instead of the whole table each time. |
| Soft delete | Marking a record as deleted without erasing it, so history is kept. |
| Pipeline | One automated step, such as 'load customers into Bronze'. |
| Orchestration | Running pipelines in the right order, retrying failures and holding back steps whose inputs failed. |
| Metadata | Data about the data: here, the rule book that tells the system which pipelines exist and how they run. |
| Watermark | A bookmark recording the last batch a pipeline processed, so the next run only does new work. |
| Reconciliation | Comparing counts and totals before and after a step to prove nothing was lost or changed. |
| Masking | Replacing personal details with stars, for example a***@example.com. |
| Token | A stable code standing in for a real value, so records can still be joined without exposing the value. |
| Vault | A separate, encrypted store holding the real personal values. Only some roles can open it, and every opening is logged. |
| Role | A job type (analyst, branch manager...) that decides what a person may see. |
| Audit log | The permanent diary of what happened and who did it. |
| Lineage | The trail showing where a number in a report came from. |
| SQL migration | Converting reports written for an old database into the SQL used on AWS, then proving the results match. |
| Athena / Glue | AWS services for querying files in S3 with SQL (Athena) and keeping the table catalogue (Glue). |
| Parquet | A compact column-based file format used to store the layers. |

## Questions and problems

**It says 'run the pipelines first' or a page is empty.**  
Nothing has been created yet. Go to Start here and press steps 1 and 2.

**Why does the first action take so long?**  
The data engine (Spark) needs about ten seconds to start, and processing runs in a separate step. Later runs are quicker.

**Will 'Create sample bank data' delete my work?**  
It resets the data created by this project (the lake, source files and run history). It does not touch anything outside the project folder.

**Why are names and phone numbers stars?**  
Personal details are masked by design in every layer that can leave the machine, and in the dashboard. Pick a role that is allowed to unmask them.

**Why do some records end up in quarantine?**  
The generated data contains deliberate mistakes (missing keys, impossible values, duplicates). Quarantine shows each record with the reason it was set aside.

**A check is red. Is something broken?**  
Maybe by design: the 'Break something on purpose' tool creates a discrepancy to show detection. Otherwise the message names the first step and the reason; use Repair, or check Activity & alerts.

**Is any of this real bank data?**  
No. Everything is synthetic and the code is original.

**Can I change what runs?**  
Yes, in Technical view, Control room: untick is_active on a pipeline. Dependent steps will then be held back.

## What each page does (details)

| Page | What it is | How to use it |
|---|---|---|
| Start here | A one-screen summary of the project and what state it is in right now. | Follow the three numbered steps from left to right. Each step turns green when it is done. |
| Bring data in | Where the source files come from. Every file that arrives is logged, and a file with the same content is never loaded twice. | Use the buttons to create fictional bank data or add a new day of activity. The table at the bottom is the receipt for every file. |
| Bronze: the untouched copy | A faithful copy of what arrived, stored as text, with the file name and load time added. Nothing is fixed or removed here. | Pick a table to see its first rows. The summary shows how many files loaded, were skipped as duplicates or were rejected. |
| Silver Merge: apply the changes | Applies new, changed and deleted records to the current picture of each table. Deleted records are flagged, not erased. | The big numbers add up what happened to the records: new, changed, deleted, ignored (too old) and duplicates removed. |
| Silver Transform: clean and protect | Fixes formats, checks the rules (for example, a balance cannot be text), hides personal details and sets aside bad records with the reason. | Pick a table to see why records were set aside and which columns are hidden. |
| Gold: ready-made reports | Summary tables built for the business: branches, customers, deposits, loans, transactions. | Open a tab to see a chart and the table behind it. The Lineage tab shows exactly which source column each report column comes from. |
| Control room | The rule book that decides which steps run, in what order, how often a failed step retries and what waits for what. | Press Run to process data. Untick is_active on a step in the table to switch it off; that is all it takes to change the behaviour. |
| Old SQL to new SQL | Converts reports written in an old bank database's SQL dialect into the SQL used on AWS, and proves the answers are identical. | Press the button. Each query shows the old text, the new text, which rules were applied and whether the results match. Unsupported syntax is reported, never guessed. |
| Can I trust the data? | Counts the records at the start and the end of every step and compares them, so nothing is lost or changed silently. | Press Run the checks. Green means everything matches. Red names the first step where it stopped matching and why. |
| Privacy & access | Personal details (names, emails, phone numbers) are hidden everywhere in the reports. The real values sit in a separate encrypted vault that only some roles can open. | Pick a role in the left bar, look up a customer and press the unmask button. Allowed roles see real values; others are refused, and both outcomes are logged. |
| Activity & alerts | A diary of everything the system did, plus alerts for anything that needs attention. | Look at the alerts first. Open a tab for the detail of runs, file loads, record changes and errors. |
| Business insights | The charts a bank manager would use to take decisions. They are built only from the finished Gold reports. All numbers are fictional. | Pick a tab. Hover over a chart for exact values. |
| Follow one table | Follows one table from the raw file through every stage to its report, showing the row count at each step. | Pick a table and read the numbered list from top to bottom. The tabs show the same rows at each stage. |
| Browse any table | A plain table browser for every dataset in the lake. Sensitive values are masked. | Pick a layer and a table, optionally filter by text. |
| Look up a customer | Browse fictional customers and see one customer's whole picture: accounts, deposits, loans and recent activity. | Search or choose a customer. Names and contacts show as stars unless the role in the left bar is allowed to see them. |
| How to use this site | Instructions, a five-minute demo script, a glossary and answers to common questions. | Read top to bottom once, then use it as a reference. |
